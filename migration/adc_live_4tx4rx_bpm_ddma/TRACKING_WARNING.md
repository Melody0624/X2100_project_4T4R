# 4T4R 跟踪、航迹和预警完整链路

## 数据流

`真实 ADC -> Range FFT -> BPM/DDMA -> Doppler FFT -> CFAR -> AoA -> 点云 -> 跟踪 -> 预警 -> USB TLV`

- 点云为 TLV 21。
- 航迹为 TLV 22，沿用原 2T4R `NEW_PROTOCOL_ENABLE` 的 18 字节对象格式。
- 预警为 TLV 24，沿用原 2T4R 的 248 字节 `WarnResult` 格式。
- 跟踪和预警均为本目录可审查源码，不调用闭源的 `libmmw_tracking.a` 或
  `libmmw_warning.a`。

## 跟踪器

`radar_tracking.c` 使用固定容量、无动态分配的恒速 alpha-beta 跟踪器。每帧先预测，
再以二维位置和径向速度门限做全局贪心最近邻关联。连续命中 3 帧后输出成熟航迹；
成熟航迹允许丢失 5 帧，之后删除。ID 为 1..254，分配时避开正在使用的 ID。

输出位置、速度、航向和尺寸使用原上位机量化规则：

- `x/y = (value_m + 255) * 8`
- `vx/vy = (value_mps + 102) * 20`
- `heading = (degree + 180) * 2.5`
- `length/width = value_m * 10`

## 预警器

`radar_warning.c` 当前采用后装坐标：车辆后方目标 `x_output < 0`，车辆左侧
`y_output > 0`。默认区域和门限是可修改的工程初值：

| 功能 | 默认区域/条件 |
| --- | --- |
| BSD | 后方 0.5..8 m，左右侧向 0.5..4.5 m |
| AOA | 后方 0.5..25 m，同侧区域，接近速度至少 1 m/s |
| LCA | 后方 0.5..70 m，同侧区域，TTC 不大于 5 s |
| RCW | 后方 0.5..100 m，中线左右 1.75 m，TTC 不大于 4 s |

警告连续满足 2 帧才置位，连续不满足 3 帧才清除。TTC 根据航迹相对位置和速度的
二维最近点时刻计算。当前没有有效自车速度/CAN输入，所以这里使用相对航迹速度，
不能宣称等同于原量产 2T4R 的地面绝对速度预警策略。

## 验证边界

主机测试覆盖成熟确认、ID 保持、交叉目标、短时丢点、删除、BSD/AOA/LCA/RCW、
TTC 和消抖；合成 ADC 的 150 帧完整链路也检查了航迹输出。ASan/UBSan 已通过。

这些测试只证明软件流程和协议自洽。BPM 512项码表、code 0起点、逐帧复位和
TX/RX相位中心几何已经取得资料；逐TX DDMA相位/子带映射、芯片通道与天线的
实际顺序、16路复数校准和76.8 GHz射频配置仍未闭环。因此真实点云、航迹和预警
只能作为联调诊断结果，不能作为道路性能或安全功能验收结果。
