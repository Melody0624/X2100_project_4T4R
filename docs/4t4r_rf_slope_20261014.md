## 位分布与实际值

截图显示 ChirpProfileRam0 的 FSTEP 为 profile bits 44:31。随附映射进一步分解为：

- 第一个 32 位字的 bit31：FSTEP bit0。
- 第二个 32 位字的 bits12:0：FSTEP bits13:1。
- 第一个字的 bits30:0：FSTART。
- 第二个字其余位：INTERCHIRP、T_TXSTART 和 T_ADCSTART。

因此：

```text
FSTEP = (word0 >> 31) | ((word1 & 0x1FFF) << 1)
1 LSB = 320e6 * 320e6 * 16 / 2^24 = 97.65625 kHz/us
旧值 0xC8 = 200：19.53125 MHz/us
新值 0xAB = 171：16.69921875 MHz/us
```

无法用此量化步长精确表示 16.69900000 MHz/us；0xAB 是最近值，与目标相差约 0.00131%。软件波形参数仍使用原先要求的 16.699 MHz/us。

SPI 配置行起点为 `0x0018`，本次修改前后：

| 字 | 原值 | 新值 |
|---|---|---|
| word0 | `0x0EE6C000` | `0x8EE6C000` |
| word1 | `0x08206064` | `0x08206055` |
| word2 | `0x001F905C` | 保持 |

word0 的最高位属于 FSTEP，因此本次没有改变 FSTART 的低 31 位。
截图中的其他值属于截图所用配置，不整行复制；原四发表的时序、ADC、TX、共同 BPM、DDMA 和其他寄存器字均保持。

## 校验和当前状态

`tools/test_4t4r_rf_slope.py` 使用 C 预处理器检查正常 BPM、关闭 BPM、合并 ADC 输出等条件分支：每个分支均为 93 行，行顺序、地址、长度及其他数据字完全相同，只有两个 FSTEP 字段发生变化。

编译检查使用独立目录和输出目录，MIPS 校验会逐字验证 ELF 中实际链接的完整寄存器表，并与四发适配的基线提交 `710a53b` 核对算法源码。

普通四发表已接入。斜率调整时先生成 RF_READY=0 的诊断包；随后按用户要求生成实验上板包，当前 SOURCE_4T4R_RF_READY=1。
硬件移相器校准已适配全部四路 TX、8 子带和对应相位序列，正常工作收敛检查同步新斜率；粗扫/细扫保留与其专用寄存器表匹配的 19.53125 MHz/μs 和 53.33 MS/s。
实验包为 `artifacts/source4t4r_live_20261014`，配置 `MT4T4R_Source_16p699_16CH_256P32T_OTA_20261014.cfg`，RTOS 911860 字节，force_erase=1。编译与离线验证通过，实际射频时序、连续采样及新波形下标定效果尚待上板验证。
