# B 版两发四收源码默认幅相补偿和角度表修正

## 原因

此前 `tools/package_2t4r_tx01_compare.py` 的 `prepare()` 在独立构建目录替换 `board_calib_config.c` 的 Barracade 分支，生成的烧录包使用用户八通道系数，但主源码仍保留厂家默认值。因此主源码与已发布包的默认矩阵不一致。

已检查 `artifacts/2t4r_rcs_reference_20261013/zero.elf`，其 `angCalibMat` 与用户提供的 16 个 float32 数值逐字节一致。该包的校准矩阵没有因本次发现而被判定为厂家值。

## 修正

在主源码 `X2100_project-main/firmware/x2100/freertos/vendor/motor_cycle_demo/src/board_calib_config.c` 的 `BOARD_ANTENNA_2T4R`、`BOARD_TYPE_BARRACADE` 分支，直接保存用户提供的八通道复数系数，顺序为 TX0RX0～TX0RX3、TX1RX0～TX1RX3。其他板型的历史矩阵保留。

| 通道 | 实部 | 虚部 |
|---|---:|---:|
| TX0RX0 | 1.000000 | 0.000000 |
| TX0RX1 | -1.199234 | 0.340255 |
| TX0RX2 | -0.481211 | -0.991089 |
| TX0RX3 | 0.914203 | 0.373536 |
| TX1RX0 | 0.413993 | 1.169006 |
| TX1RX1 | -0.884424 | -1.231216 |
| TX1RX2 | 0.929756 | -1.007362 |
| TX1RX3 | -0.094489 | 1.232397 |

这组数据包含幅度和相位的复数乘法补偿，不是以度为单位的相位角。

## 运行时来源

源码默认矩阵在没有有效覆盖数据时使用。`vendor.c` 启动时可用非空的 Flash `PARAM_ANG_CALIB_MAT` 覆盖默认矩阵；主动校准或 `angCalibMat write` 也可更新系数。`board_calib_init()` 将当前矩阵复制到算法使用的备份，不重新写回编译默认值。

## 验证

`tools/test_2t4r_default_calibration.sh` 直接编译主源码的板级配置文件，不经过打包替换。
修正前测试在矩阵字节比较处失败，修正后通过；同时验证备份初始化及运行期间已更新矩阵的保留。

## 角度表和阵列几何同步

角度表原先也只在构建副本替换，主源码 Barracade 分支保留厂家表，以 -3.593931、0.527261、1.122901 等数值开头。现已同步为此前 B 阵列校准包使用的理论表：

```text
lambda = 299792458 / 76.5e9
spacing = -0.00196 / lambda
k = i if i < 64 else i-128
angle[i] = asin(k / (128*spacing)) * 180/pi
```

`angFFT_interp` 共 128 个 float；例如索引 0=0°、16=-14.473193°、32=-29.990343°、64=88.615532°、96=29.990343°、127=0.895022°。端点由实际间距计算，不手动强制为 ±90°。

同时同步 `set_params.c` 的有符号最小间距和 `memory_pool.c` 的八个阵元位置，限定为当前两发 Barracade 板型；其他板型保留原正间距。插值开关仍为 true，Flash 有效角度表和主动角度校准仍可覆盖默认表。

直接编译主源码的测试逐项验证全部 128 个理论值。全流程回归启用 ASan/UBSan，验证实际初始化时的间距、八项坐标、128项角度映射，以及 6 个 ADC→FFT→DDMA→CFAR→AoA→后处理→RCS 用例和主动校准保存流程，均通过。测试脚本默认选择理论表验证；打包脚本避免重复插入已同步的间距设置。

本次提交同步修正主源码默认值，没有重新生成烧录包。已发布烧录包的八通道编译矩阵及理论角度表与本次修正值相同；设备实际使用哪组系数及角度表仍取决于其 Flash 和运行期间的配置。提交版本以 Git 历史为准。
